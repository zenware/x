# 🎯 Problem (Why)
`devenv up` currently fails during Nix evaluation because shell variables in process/script blocks are being interpolated as Nix expressions. This blocks developers from starting the local stack and breaks the expected one-command bootstrap workflow.

# 📋 Acceptance Criteria
- [ ] Running `devenv up` starts configured services/processes without Nix interpolation errors.
- [ ] `glean-init` and `glean-test` scripts execute with shell environment variables resolved at runtime, not during Nix evaluation.
- [ ] Add an automated config validation check (or documented command) that catches this interpolation class before merge.

# 🧪 Slice Test Scenario
- **Given** a clean local clone with `devenv.nix`
- **When** a developer runs `devenv up` and invokes `devenv tasks run glean-init`
- **Then** processes start, scripts run, and no `${GLEAN_*}` evaluation errors appear from Nix parsing

# 🚫 Negative Constraints
- Do not hardcode machine-specific absolute paths.
- Do not replace runtime shell variables with static secrets in Nix source.

# 🧠 Implementation Plan

# 📝 Implementation Notes
- Escaped runtime shell env vars in `devenv.nix` script/process blocks using `''${...}` so Nix no longer evaluates them as Nix expressions.
- Verified `devenv.nix` parses successfully with `nix-instantiate --parse`.
- Fixed Darwin shell realization failure by switching away from the broken `languages.rust` wrapper path to direct Nixpkgs Rust toolchain packages in `devenv.nix`.
