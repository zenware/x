# 🎯 Problem (Why)
Untrusted or buggy plugins must be isolated so they cannot crash orchestration or exhaust shared resources.

# 📋 Acceptance Criteria
- [ ] End-to-end feature flow is implemented and demoable: From a fresh case, execute "Sandbox plugin execution with resource limits" end-to-end and verify investigator-visible output through API and UI surfaces.
- [ ] Investigator-visible outcome is accessible (UI and/or API) with realistic sample data, not just internal wiring.
- [ ] At least one automated integration/e2e check is added that fails before and passes after this slice.

# 🧪 Slice Test Scenario
- **Given** a clean local environment and a new investigation case
- **When** the operator triggers this slice via normal product workflow
- **Then** the expected outcome is visible in the product, persisted correctly, and verifiable by automated tests

# 🚫 Negative Constraints
- Do not execute plugins with unrestricted host privileges.
- Do not swallow plugin runtime errors.
